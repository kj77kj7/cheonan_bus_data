# 추가로 필요한 데이터와 확보 경로

> 작성 기준: 2026-08-14
> 짝 문서: [DESIGN.md](DESIGN.md) — 왜 이 데이터가 필요한지는 그쪽 4~6장 참고

지금 가진 것은 **"버스가 언제 어디 있었나"** 뿐이다.
[DESIGN.md](DESIGN.md) 5·6장에서 드러난 두 구멍(개편 전 데이터 없음 / 승하차 데이터 없음)을
포함해, 필요한 데이터를 **확보 난이도 순**으로 정리한다.

## A. 즉시 확보 가능 — API·다운로드

이 다섯은 오늘 바로 받을 수 있다. **모두 소급 수집이 되므로 급하지 않다**
(실시간 버스위치와 달리 과거 데이터가 서버에 남아 있다). 단 4번은 예외다.

### A-1. 기상 관측 자료 ★필수

`DESIGN.md` 5.3 **다안**(날씨를 처치로 삼는 DID)과 6.1 지연예측 모델의 핵심 외생변수.

| 항목 | 내용 |
|---|---|
| 데이터셋 | 기상청_지상(종관, ASOS) 시간자료 조회서비스 |
| 링크 | https://www.data.go.kr/data/15057210/openapi.do |
| 엔드포인트 | `https://apis.data.go.kr/1360000/AsosHourlyInfoService/getWthrDataList` |
| 제공 | 시간별 기온·강수량·풍속·습도·시정 |
| 소급 | **가능** (과거 자료 조회) |
| 한도 | 개발계정 10,000건/일 |

- **천안 관측지점 번호를 먼저 확인해야 한다.**
  [지상기상관측 지점정보 조회서비스](https://www.data.go.kr/data/15139439/openapi.do)로 조회.
- 수집 기간(7/31~8/21) 22일 × 24시간 = 528건이면 끝난다. 한도 여유가 크다.
- 이미 인증키가 있으므로 **활용신청만 추가**하면 된다. 같은 키를 쓴다.

> 구현: `src/collect/fetch_weather.py` — `config.py`에 `BASE_ASOS` 추가

### A-2. 공휴일 정보 ★필수

요일 효과와 공휴일 효과는 다르다. 8월 15일(광복절)이 수집 기간에 들어 있어
이 구분 없이는 그날 데이터를 잘못 해석하게 된다.

| 항목 | 내용 |
|---|---|
| 데이터셋 | 한국천문연구원_특일 정보 |
| 링크 | https://www.data.go.kr/data/15012690/openapi.do |
| 엔드포인트 | `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService` |
| 주의 | 오퍼레이션이 여러 개다. 공휴일은 `getRestDeInfo` 계열을 쓴다 |

- 한 해치가 수십 건이라 **CSV로 한 번 받아 고정해도 된다.** API를 굳이 안 붙여도 무방.

### A-3. 천안시 시내버스 운수업체별 노선현황

| 항목 | 내용 |
|---|---|
| 데이터셋 | 충청남도 천안시_시내버스운수업체별노선현황 |
| 링크 | https://www.data.go.kr/data/15085744/fileData.do |
| 형식 | 파일 (CSV/JSON/XML), 최신 갱신 2026-03-12 |
| 제공 | 노선번호, **운수업체명**, 1회 운행거리(편도 km) |

- **운수업체가 지연예측 모델의 설명변수가 된다.** 업체별 운행 관행 차이가 정시성에
  영향을 준다는 건 흔한 발견이고, 정책 제안으로도 이어진다.
- 1회 운행거리는 우리가 좌표로 계산한 거리의 **검증용**으로도 쓸 수 있다.

### A-4. 버스 도착예정정보 (TAGO) ⚠ 소급 불가

| 항목 | 내용 |
|---|---|
| 데이터셋 | 국토교통부_(TAGO)_버스도착정보 |
| 링크 | https://www.data.go.kr/data/15098530/openapi.do |
| 엔드포인트 | `https://apis.data.go.kr/1613000/ArvlInfoInqireService` |

**이건 지금 결정해야 한다.** 실시간 API라 나중에 받을 수 없다.

- `config.py`에 `BASE_ARRIVAL_INFO`가 **이미 정의돼 있다.** 처음부터 염두에 뒀던 것으로 보인다.
- 얻는 것: 정류장별 **도착예정시간(BIS가 시민에게 안내하는 값)**
- 왜 가치 있나: 우리가 재는 건 "실제 소요시간"인데, 여기에 "안내된 예정시간"을 붙이면
  **BIS 안내 정확도**를 평가할 수 있다. `안내 오차 = 실제 도착 - 예정 안내`
  → 시민 체감과 직결되는 지표라 정책 제안으로 강력하다.
- 비용: 정류장 단위 호출이라 전수는 부담. **처치군 5개 노선의 주요 정류장 20~30곳**으로
  한정하면 현재 호출 여유(하루 3.5만/50만) 안에서 충분히 가능하다.

> 판단이 필요하다. 남은 수집 기간이 7일뿐이라 표본이 얇아진다.
> "안내 정확도"를 산출물에 넣을 것인지 지금 정해야 한다.

## B. 신청·청구 필요 — 회신까지 시간이 걸린다

### B-1. 교통카드 승하차 데이터 ★★ 산출물 C의 근본 해결책

`DESIGN.md` 6.2에서 지적한 "수요 데이터 없음"을 해결하는 유일한 정공법이다.

| 항목 | 내용 |
|---|---|
| 시스템 | 교통카드 빅데이터 시스템 (STCIS) |
| 링크 | https://stcis.go.kr/ |
| 제공 | 시내버스(마을·농어촌 포함) **노선별·정류장별 이용 지표**, 수단/목적/환승 통행량 |
| 개방 | 국토교통부가 **2025년 4월 1일부터 개방 확대** |

- 이게 확보되면 산출물 C를 "체류시간 대리지표"가 아니라 **진짜 수요 예측**으로 격상할 수 있다.
- 국토부 보도자료: [4월 1일부터 교통카드 빅데이터 개방](https://www.molit.go.kr/LCMS/DWN.jsp?fold=koreaNews%2Fmobile%2Ffile&fileName=250401%28%EC%84%9D%EA%B0%84%29+4%EC%9B%94+1%EC%9D%BC%EB%B6%80%ED%84%B0+%EA%B5%90%ED%86%B5%EC%B9%B4%EB%93%9C+%EB%B9%85%EB%8D%B0%EC%9D%B4%ED%84%B0+%EA%B0%9C%EB%B0%A9%28%EC%83%9D%ED%99%9C%EA%B5%90%ED%86%B5%EB%B3%B5%EC%A7%80%EA%B3%BC%29.pdf)
- 샘플로 먼저 감을 잡을 수 있다:
  [한국교통안전공단_교통카드데이터 이용량(샘플)](https://www.data.go.kr/data/15118210/fileData.do)

> **가장 먼저 알아보셔야 할 항목이다.** 신청 절차·자격·소요 기간이 확인돼야
> 산출물 C의 방향(진짜 수요 예측 vs 체류시간 추정)을 확정할 수 있다.

### B-2. 2023년 BIS 운행이력 ★★ DID의 '개편 전'

`DESIGN.md` 5.2의 구멍을 메우는 유일한 방법.

| 항목 | 내용 |
|---|---|
| 대상 | 천안시청 (BIS 운영: https://its.cheonan.go.kr) |
| 방법 | 정보공개청구 (열린정부 www.open.go.kr) |
| 요청 내용 | 2023년 시내버스 정류장 통과 이력 또는 노선별 운행기록 |

- **개편 시행일이 2024년 1월 27일**로 확인됐다. 따라서 '전' 구간은 2023년,
  가급적 **2023년 7~8월**(계절·학사일정을 맞춰 우리 수집분과 대응)을 요청해야 한다.
- 회신 여부·데이터 형식이 불확실하다. **받으면 DID 성립, 못 받으면 5.3의 나+다안**으로 간다.
- 청구는 걸어두되, **프로젝트 일정을 여기에 걸지 않는다.**

### B-3. 노선 개편 전후 대응표

| 항목 | 내용 |
|---|---|
| 대상 | 천안시청 대중교통과 |
| 요청 내용 | 2024.1.27 개편 전후 노선 대응표 (폐선/신설/변경 구분) |

- 대조군의 필수 요건인 **"개편으로 변경되지 않았을 것"**을 확정하는 자료.
  `rank_control_candidates.py`가 이미 "이건 회신 전 잠정안"이라고 명시해 두었다.
- **부분적으로는 공개 자료로도 확인 가능하다.** 개편안이 시 홈페이지에 공개된 바 있고,
  권역별 개편 내용(도심권/북부권/동부권/남부·아산권/폐선)이 정리된 자료가 돌아다닌다.
  청구 회신 전이라도 **교차 검증용**으로 쓸 수 있다.

## 구현 시 주의 [확정 — 이미 겪음]

- **모든 엔드포인트를 `https://`로 쓴다.** 평문 HTTP(80)는 2026-08-02 무렵부터
  응답하지 않는다. TCP 연결은 되고 응답만 오지 않아 장애로 오인하기 쉽다.
- **인증키는 디코딩 키를 쓴다.** `urlencode`가 자동으로 퍼센트 인코딩한다.
- **요청 속도를 편다.** 인증키 단위로 429가 걸린다. 실시간 수집기가 이미
  하루 3.5만 건을 쓰고 있으므로, 추가 수집기는 `Pacer`를 재사용해 간격을 둔다.
