## 한 줄 요약

> **천안시 시내버스 265개 노선의 실제 운행을 3주간 60초 간격으로 관측해,
> 공표된 배차·소요시간과 실제가 얼마나 다른지 구간 단위로 계량하고,

핵심 가치는 **"실측"** 이다. 천안시가 공표하는 배차간격은 계획값이고,
시민이 겪는 건 실제값이다. 그 간극을 숫자로 보인 자료가 지금 없다.

## 1. 데이터셋 — 재사용 가능한 자산

수집이 끝나면 **다른 사람이 다시 만들 수 없는 자산**이 남는다.
실시간 데이터는 소급 수집이 불가능하므로 이 기간의 기록은 이것뿐이다.

| 산출물 | 규모(21일 추정) | 설명 |
|---|---|---|
| `data/realtime/*.csv` | **약 125만 행 / 155 MB** | 원본 관측 (core 60초 + network 600초) |
| `processed/segments.csv` | **약 34만 개** | 정류장 A→B 구간 통과 표본 (12일 실측 295,140) |

| `processed/headway.csv` | — | 정류장별 실측 배차간격 |
| `processed/baseline.csv` | 1,361 구간 | 구간별 자유흐름 기준선 |

**커버리지**

- 노선 265개 (core 정밀 37 routeId + network 전수)

- 월~일 전 요일, 06~23시 전 시간대
- 차량 약 150대/일 추적

## 2. 분석 리포트 — 경진대회 본체

### 2-1. 현황 진단 (산출물 A)

| 지표 | 내용 |
|---|---|
| **계획 대비 실측 배차간격** | 노선별로 공표값(`intervaltime`)과 실측 중앙값·분산 비교 |
| **번칭(bunching) 발생률** | 배차가 공표값의 30% 미만으로 붙은 사건 비율 |
| **구간별 지연 지도** | 1,361개 구간의 `delay_ratio`를 지도에 색으로 표시 |
| **첨두/비첨두 격차** | 08시·18시 대 심야의 구간 소요시간 배율 |
| **정시성 순위** | 노선별 소요시간 분산 기준 |

> 이 중 **번칭**이 가장 설득력 있는 카드다. "배차 10분"이라고 안내하면서
> 실제로는 두 대가 붙어 오고 20분을 기다리는 상황을 숫자로 보이는 것이라,
> 시민 체감과 직결되고 개선 방안(배차 조정·중간 대기)도 명확하다.

### 2-2. 개편 효과 또는 노선 간 비교 (산출물 D)

`DESIGN.md` 5.3의 어느 안을 택하느냐에 따라 결과물이 달라진다.

| 안 | 결과물 | 강도 |
|---|---|---|
| 가 (BIS 이력 확보) | 2024.1 개편의 정시성 개선 효과 (DID 추정치) | **인과 주장 가능** |
| 나 (횡단면 비교) | 개편 노선 vs 미개편 노선의 현재 성능 차이 | 기술통계 |
| 다 (날씨 DID) | 강우가 구간 지연에 미치는 인과 효과 | **인과 주장 가능** |

**다안은 지금 데이터로 확실히 나온다.** "비 오는 날 첨두시간대 지연이 몇 % 증가"는
그 자체로 정책 함의가 있다(우천 시 증차·신호 우선).

### 2-3. 개선 우선순위 제안

지연이 심한 구간을 **개선 여지 × 영향 인원**으로 정렬해 상위 N개 제시.

```
우선순위 점수 = (delay_ratio - 1) × 해당 구간 통과 운행 수 × 노선 중요도
```

- 이게 "정책 아이디어 경진대회"의 최종 답변에 해당한다.
- 구간마다 **왜 느린지**(신호·회전·정차 과다)를 좌표와 함께 붙이면 실행 가능한 제안이 된다.

## 3. 예측 모델 (산출물 B)

| 항목 | 내용 |
|---|---|
| 입력 | 구간, 시각, 요일, 공휴일, 날씨, 직전 구간 지연, 앞차 간격 |
| 출력 | 해당 구간 예상 소요시간(초) |
| 학습 표본 | 약 34만 개 |
| 평가 | MAE(초), 정시 도착(±2분) 적중률 |
| 비교 대상 | **공표 배차 기반 단순 예측** |

**"현재 BIS 안내보다 몇 % 정확하다"** 를 보이는 것이 목표다.
모델 자체보다 **특징 중요도**가 정책 언어로 번역된다 —
"지연의 최대 요인은 X" 라는 결론이 곧 제안 근거가 된다.

> [DATA_SOURCES.md](DATA_SOURCES.md) A-4(도착예정정보)를 수집하면
> **실제 BIS 안내값과 직접 비교**할 수 있어 이 주장이 훨씬 강해진다.
> 다만 소급 불가라 지금 결정해야 한다.

## 4. 정류장 혼잡도 추정 (산출물 C)

교통카드 데이터 확보 여부로 갈린다.

| 조건 | 결과물 |
|---|---|
| 확보 시 | 정류장별 시간대별 **승하차 수요 예측** |
| 미확보 시 | 정류장 **체류시간 기반 혼잡도 추정** (대리지표) |

미확보 시에도 "체류시간이 긴 정류장 = 승하차가 몰리는 정류장"이라는 상대 순위는
낼 수 있다. 다만 **산출물 이름을 정직하게 붙여야 한다.**

## 5. 코드·운영 자산

이미 완성돼 검증된 부분이다. 그 자체로 재현 가능성의 근거가 된다.

| 자산 | 상태 |
|---|---|
| 수집 파이프라인 (단계 1~3) | **완성·가동 중** |
| 무인 운영 (작업 스케줄러 등록/해제/재시작) | **완성·20일 가동 검증** (재부팅 시 1분 내 자동 복구) |
| 건강 점검 (`check_health.py`) | **완성** — 경보, 저장 실패, 가동률 |
| 장애 대응 이력 | HTTP 차단·429·Writer 버그를 겪고 고친 기록이 커밋에 남음 |

> **외부 패키지 없이 표준 라이브러리만으로 만든 점**이 강점이다.
> 지자체가 그대로 받아 돌릴 수 있다. 실제로 3주 무인 운영을 견뎠다는 실적도 있다.
