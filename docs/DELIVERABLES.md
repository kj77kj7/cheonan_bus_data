## 한 줄 요약

> **천안시 시내버스의 배차를 줄이거나 노선을 조정하면 이용객이 얼마나 늘어나는지를
> 실측 데이터로 추정하고, 개선 시나리오별 증가량과 우선순위를 제시한다.**

핵심은 **"실측"** 이다. 천안시가 공표하는 배차는 계획값이고 시민이 겪는 것은
실제값이다. 그 간극을 잰 자료도, 배차와 이용률의 관계를 천안 데이터로 추정한
자료도 지금 없다.

## 2. 산출물 A — 현황 진단

> **지금 데이터로 전부 나온다.** 추가 확보에 의존하지 않는다.

| 지표 | 내용 |
|---|---|
| **계획 대비 실측 배차** | 노선별 공표값 vs 실측 중앙값·분산 |
| **번칭 발생률** | 배차가 공표값의 30% 미만으로 붙은 사건 비율 |
| **시간대별 이용 프로파일** | 노선·정류장별 첨두 구조 |
| **구간별 지연 지도** | 1,361개 구간의 `delay_ratio` 를 좌표에 |
| 정시성 순위 | 노선별 소요시간 분산 |

> **번칭이 가장 센 카드다.** "배차 10분"이라 안내하면서 실제로는 두 대가 붙어
> 오고 20분을 기다리는 상황을 숫자로 보이는 것이라, 시민 체감과 직결되고
> 개선책(배차 조정·중간 대기)도 명확하다.

## 3. 산출물 B — 서비스 탄력성 추정 ★ 본체

[DESIGN.md](DESIGN.md) 4장의 노선 고정효과 패널로 **β** 를 추정한다.

```
"배차간격을 X% 줄이면 이용객이 Y% 늘어난다"
```

| 항목 | 내용 |
|---|---|
| 표본 | 198노선 × 6시점 |
| 식별 | 노선 고정효과 — 같은 노선 안의 배차 변화만 본다 |
| 통제 | 권역 인구·고용, 운수업체, 노선 길이, 강수, 공휴일, 시점 |
| 부가 | **공표 배차 vs 실측 배차** 중 무엇에 반응하는가 |

마지막 줄이 흥미로운 결과가 될 수 있다. 실측 쪽 계수가 크게 나오면
**"배차표를 고치는 것보다 지키는 것이 먼저다"** 라는 정책 메시지가 된다.

> **전제**: 배차간격 변경 이력이 있어야 한다 ([DATA_SOURCES.md](DATA_SOURCES.md) A-1).
> 못 받으면 [DESIGN.md](DESIGN.md) 6장의 차선책으로 내려가고, 주장 강도가 떨어진다.

## 4. 산출물 C — 시나리오 시뮬레이션과 우선순위 ★ 최종 답변

β 를 써서 정책 질문에 숫자로 답한다.

| 질문 | 결과물 |
|---|---|
| 구도심 노선 배차를 30분 → 15분 | 노선별 예상 증가 인원 |
| 어느 노선부터 손대야 하는가 | **증차 1대당 증가 인원** 순위 |
| 신설 노선의 예상 수요 | 권역 인구·고용 기반 이전 추정 (구간 추정치와 함께) |

**이 우선순위 표가 경진대회의 최종 답변이다.** "이 노선 셋에 버스 N대를 더 넣으면
연 M명이 늘고, 대당 효율이 가장 높다"까지 간다.

## 5. 산출물 D — 구간 소요시간 예측 (보조)

원래 본체였다가 투입으로 자리를 옮겼다.

| 항목 | 내용 |
|---|---|
| 예측 대상 | 구간 `travel_sec` |
| 표본 | 약 34만 |
| 모델 | LightGBM |
| 평가 | MAE, 정시 도착(±2분) 적중률 |

산출물 A 의 지연 지도와 B 의 서비스 품질 변수를 만드는 데 쓴다. 단독으로도
"지연의 최대 요인은 X" 라는 특징 중요도를 낸다.

## 6. 코드·운영 자산

| 자산 | 상태 |
|---|---|
| 실시간 수집 파이프라인 | **완성·가동 검증** (재부팅 시 1분 내 자동 복구) |
| 무인 운영 (작업 스케줄러) | **완성·20일 이상 가동** |
| 건강 점검 `check_health.py` | **완성** |
| STCIS 수집기 2종 | **완성·검증** (사이트 CSV 와 대조 일치) |
| 장애 대응 이력 | HTTP 차단·429·Writer 버그·타임아웃 재시도를 겪고 고친 기록이 커밋에 |

> **수집기가 외부 패키지 없이 표준 라이브러리만으로 돌아간다.** 지자체가 그대로
> 받아 쓸 수 있고, 실제로 무인 운영을 견뎠다는 실적이 있다.

## 지금 가능한 것 vs 확보가 필요한 것

| 산출물 | 현재 데이터로 | 추가 필요 |
|---|---|---|
| A. 현황 진단 | **전부 가능** | — |

그것은 **배차간격 변경 이력 하나**에 달려 있다.
