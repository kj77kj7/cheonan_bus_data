## 4. 이미 겪은 함정 — **다시 밟지 말 것**

수집 3주 동안 실제로 데이터를 날린 사고들이다. 전부 수정됐고 커밋에 기록돼 있다.

| # | 사고 | 원인 | 조치 (커밋) |
|---|---|---|---|
| 1 | 08-01 하루치 전량 유실 | `Writer.close()`가 `self.day`를 안 비워, 01:00에 닫힌 writer를 05:30에 그대로 재사용 → `NoneType.writerow` | `af57250` |
| 2 | 08-02~03 대량 실패 | 포털이 **평문 HTTP(80)를 차단**. TCP는 연결되고 응답만 안 와서 서버 장애로 오인 | `f3a041f` — 전 엔드포인트 `https://` |
| 3 | HTTPS 전환 직후 429 폭증 | 응답이 4.5초→0.1초로 빨라져 순간 요청 속도가 9건/초까지 튐. **429는 인증키 단위** | `630d56a` — `Pacer`로 요청 간격 강제 |
| 4 | 위 1번이 경보에 안 걸림 | `sweep()`이 쓰기 예외를 삼켜 "실패 0건"으로 보고. 이틀간 정상으로 보임 | `f3a041f` — 저장 실패를 경보 대상에 |
| 5 | 점검 리포트가 정상을 이상으로 보고 | 순회가 43초로 길어지자 CSV 타임스탬프 묶기가 순회를 쪼갬 | `818c902` — 로그에서 순회 시작 복원 |
| 6 | 복구 후에도 경보가 안 지워짐 | 해제 조건이 streak 기반인데 재시작하면 streak이 0 | `818c902` — 조건 없이 해제 |

### 반드시 지킬 규칙

- **모든 API는 `https://`.** 평문 HTTP는 응답하지 않는다.
- **인증키는 디코딩 키.** `urlencode`가 자동으로 퍼센트 인코딩한다.
  (현재 키는 순수 16진수라 인코딩/디코딩이 동일해 우연히 무해)
- **새 수집기를 붙일 때 `Pacer`를 재사용한다.** 429는 키 단위라 다른 프로세스까지 죽인다.
- **PowerShell 스크립트는 UTF-8 BOM으로 저장한다.** BOM이 없으면 PS 5.1이 cp949로
  읽어 한글 주석에서 파싱이 깨진다.
- **작업 스케줄러 반복 트리거의 Duration은 비운다.** `[TimeSpan]::MaxValue`를 넘기면
  `P99999999DT23H59M59S`로 직렬화돼 등록이 거부된다.

## 9. 운영 상 알아둘 것

- 수집기 자원 사용은 **CPU 0%, 메모리 30MB 수준**. 다른 작업에 영향 없다.
- 호출량은 하루 core 약 45,000 / network 약 33,000. **일 한도 500,000건** 대비 여유가 크다.
- 디스크는 하루 약 7 MB. 3주 전체로도 200 MB 미만.
- Windows 업데이트 일시 중지 **2026-08-31까지** 설정돼 있다.
